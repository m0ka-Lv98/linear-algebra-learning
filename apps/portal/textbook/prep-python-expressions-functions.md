# Pythonの式・変数・関数：教科書

## この章で理解すること

数式を小さなPythonプログラムへ移し、演算、制御構造、関数、型注釈、検算を安全に扱う。

- Pythonの基本演算子と数学記号の対応を説明できる
- 条件分岐・反復・関数を使って小さな数値計算を記述できる
- 引数・戻り値・ローカル変数・型注釈の役割を説明できる
- 小さな手計算とコード結果を相互に検算できる

## 前提知識

Course 00で既に登場した記号は必要に応じて復習する。新しい記号・略語はこの章の初出時に意味を定義する。ベクトルは太字小文字、行列は太字大文字で表す。コード例では、数学上の意味とPython/NumPy上の表現を混同しない。

## この章の読み方

まず「対象は何か」「入力と出力は何か」「成立条件は何か」を確認する。式変形やコード実行の前に、型・shape・定義域・添字範囲を言葉で説明する。例題では答えだけでなく、なぜその操作が許されるかを一文で述べる。最後に反例または境界例を考え、理解が条件付きであることを確認する。

## Pythonを数学の代替ではなく検算道具として使う

このCourseでPythonを使う目的は、数学をブラックボックス化することではなく、小さな計算を再現し、式の理解を検査することである。まず手計算で期待値を持ち、その後コードで確認する。コードが出した値を正解として無条件に受け入れず、入力、型、演算子、境界条件を確認する習慣をつける。
## 数値リテラルと基本型

`3` は整数 `int`、`3.0` は浮動小数点数 `float`、`True` と `False` は `bool`。Pythonでは型により演算の意味が変わることがある。例えば `/` は通常浮動小数点の除算、`//` はfloor divisionである。数値計算では整数除算を意図せず使わないようにする。
## 代入と等価比較

Pythonの `=` は数学の等号ではなく、右辺の値を左辺の名前へ束縛する代入である。等価比較は `==` を使う。`x = x + 1` は数学の方程式としては不可能だが、プログラムでは現在の `x` に1を足して新しい値を `x` へ再代入するという意味になる。
## 演算子と優先順位

加減乗除は `+ - * /`、累乗は `**`。`^` は累乗ではなくbitwise XORなので注意する。複雑な式では演算子優先順位を暗記に頼らず括弧を使う。数学式をコードへ移すときは、分子・分母、指数、負号の範囲を明示する。
## 比較と条件分岐

`< <= > >= == !=` で比較し、`if`、`elif`、`else` で条件に応じた処理を選ぶ。数値計算では定義域チェック、ゼロ除算の回避、入力検証などに使う。浮動小数点の等価比較には後のTopicで扱う許容誤差が必要なことがある。
## forとrange

反復には `for` を使える。`range(start, stop)` は `stop` を含まないため、数学の閉区間的な添字と対応付けるときにoff-by-one errorが起きやすい。例えば数学の $i=1,2,3$ は `for i in range(1,4)`。Pythonのindexが0始まりであることと合わせて確認する。
## リスト

リストは複数の値を順序付きで保持する。`values=[1.0,2.0,3.0]` の先頭は `values[0]`。リストは可変で、要素変更や `append` が元のオブジェクトに影響する。数学的ベクトルと似て見えても、リストは汎用コンテナであり線形代数の演算を自動的には持たない。
## 関数定義

`def` で処理を名前付きの関数へまとめる。引数は入力、`return` は戻り値を指定する。例えば `def affine(x,a,b): return a*x+b` は数学の $f(x)=ax+b$ に近い。ただしPython関数は副作用や例外を持てるため、数学的関数と完全に同じ概念ではない。
## ローカル変数とscope

関数内部で定義した変数は基本的にローカルscopeを持つ。外部状態へ依存する関数は挙動を追いにくくなるため、初学段階の数値関数では必要な値を引数として受け取り、結果をreturnする形を優先する。再現性とテストもしやすくなる。
## 型注釈とdocstring

`def affine(x: float, a: float, b: float) -> float:` のような型注釈は入力・出力の意図を伝える。docstringには関数の目的、引数、戻り値、前提条件を書くとよい。ただし標準Pythonの型注釈は実行時の数学的保証ではない。型注釈があるから不正入力が自動排除されるとは限らない。
## 小さな関数へ分割する

長い計算を一つの巨大な関数へ詰め込むより、「入力変換」「主要計算」「検査」のように分けると誤りを局所化しやすい。数学の導出でも中間量へ名前を付けるのと同じである。関数の入力と出力が明確なら、単体テストや再利用が容易になる。
## 検算とデバッグ

バグを見つけるには、最小の入力を使い、期待結果を手計算し、中間値を確認する。例として平方和なら `[1,2,3]` の答え14を先に求める。境界値、空リスト、0、負数なども考える。後のNumPyや機械学習でも「小さな既知ケースで検算する」方法は非常に有効である。

## 詳細例で確認する

### 例題1

**問い**：`x = 2; x = x + 3` の最終的な `x` と、数学の等式 `x=x+3` との違いを説明せよ。

**考え方**：定義・型・成立条件を先に確認し、答えを予測してから計算する。

**解答**：最終値は5。Pythonの`=`は代入で、2に3を足した値を名前xへ再束縛する。数学の等号とは意味が異なる。

**誤りを避けるポイント**：方程式なので解なしと答える。

### 例題2

**問い**：Pythonで $2^5$ を計算する正しい式を書け。

**考え方**：定義・型・成立条件を先に確認し、答えを予測してから計算する。

**解答**：`2 ** 5` で32。`2 ^ 5` はbitwise XORで7。

**誤りを避けるポイント**：`2 ^ 5` を使う。

### 例題3

**問い**：`7 / 2` と `7 // 2` の違いを答えよ。

**考え方**：定義・型・成立条件を先に確認し、答えを予測してから計算する。

**解答**：`7 / 2` は3.5、`7 // 2` はfloor divisionで3。

**誤りを避けるポイント**：どちらも整数3とする。

### 例題4

**問い**：数学の $i=1,2,3,4$ を回す `range` を書け。

**考え方**：定義・型・成立条件を先に確認し、答えを予測してから計算する。

**解答**：`range(1,5)`。stopは含まれない。

**誤りを避けるポイント**：`range(1,4)` とする。

### 例題5

**問い**：`def affine(x,a,b): return a*x+b` で `affine(3,2,1)` を計算し、各引数を数学式に対応付けよ。

**考え方**：定義・型・成立条件を先に確認し、答えを予測してから計算する。

**解答**：$a=2,x=3,b=1$ なので7。関数は $f(x)=ax+b$ を計算する。

**誤りを避けるポイント**：引数順序を $x,b,a$ と混同する。

### 例題6

**問い**：平方和を返す関数を `for` を使って書き、`[1,2,3]` で検算せよ。

**考え方**：定義・型・成立条件を先に確認し、答えを予測してから計算する。

**解答**：`total=0.0` から各valueについて `total += value**2`、最後にreturn。結果は14。

**誤りを避けるポイント**：`total = value**2` と毎回上書きする。


上の例題では、結果だけでなく、どの定義・条件を使ったかを言葉にする。自分の解答が数値だけの場合は、少なくとも一文の根拠を追加する。コード問題では実行結果だけでなく、実行前に期待する値またはshapeを書いて比較する。これにより、偶然正しい値が出た場合と、概念を理解して正しい値を予測できた場合を区別できる。

## 境界条件と反例の作り方

このTopicの公式や規則は、適用条件を外すと成立しない場合がある。境界値として0、1、空集合、長さ1の配列、定義域の端、shapeが一つだけ違う入力などを試す。さらに「よくある誤解」を否定する最小反例を自分で作る。反例が作れない場合は、用語の定義に戻り、何を変えると条件を壊せるかを考える。この作業は後続Courseで定理の仮定、数値アルゴリズムの前提、機械学習モデルの入力仕様を確認する際にもそのまま使える。

## 基本式・記法のチェックリスト

- `x = x + 1` は代入

- `**` は累乗、`^` は累乗ではない

- `range(1, 4)` は 1,2,3

- `return` は関数の出力

式を見たときは、各記号の意味、値の種類、添字範囲、必要な条件を説明できるか確認する。暗記した式を条件外で適用しない。

## よくある誤解

- **誤解**：Pythonの`=`は数学の等号と同じ
- **誤解**：`^`は累乗演算子である
- **誤解**：`range(1,4)`は4を含む
- **誤解**：型注釈があれば実行時に不正な型は必ず拒否される

誤解を見つけたら、単に「間違い」と覚えるのではなく、最小の反例を一つ作る。反例を自分で作れることは、定義を操作できているかを確認する有効な方法である。
